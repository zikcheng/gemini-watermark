# M3 — Image primitives (src/imageops.ts + src/resize.ts)

> **Base fact**: this repository is a faithful TypeScript port of
> [GeminiWatermarkTool](https://github.com/allenk/GeminiWatermarkTool) —
> a C++ tool that removes Gemini's visible image watermark via
> deterministic reverse alpha blending. The C++ source (v0.3.2, commit
> `7c6a99f`, checked out at `$GWT_UPSTREAM_DIR`) is the sole behavioral
> authority; we reproduce its behavior, quirks included, never "improve" it.
>
> **Required upstream reading (in full, before writing code)**:
> `src/core/watermark_engine.cpp` — `effective_alpha_map` and
> `create_interpolated_alpha`; the OpenCV *calls* inside
> `detect_one_variant` (cvtColor/Sobel/matchTemplate/meanStdDev usage and
> parameters). **Do not** read or reason from OpenCV's own source —
> OpenCV's numeric behavior comes exclusively from the pinned cv2 oracle
> dumps.

Prerequisite: M2 complete; locally
`pip install -r tools/reference/requirements.txt` (includes pinned
opencv-python).

## Context

Detection (M4) is three stages of classic image processing — spatial NCC
against the alpha template, Sobel-gradient NCC, and variance statistics.
The C++ side gets these from OpenCV; we reimplement just the five
operators the detector needs, each verified against **dumps generated by
the pinned opencv-python** (the "cv2 oracle"), because OpenCV's actual
numeric behavior (fixed-point grayscale, DFT-based matchTemplate,
INTER_AREA weighting) differs from textbook formulas in ways that would
silently shift detection scores.

This milestone also delivers `resize` and therefore `effectiveAlphaMap` —
the derived-size alpha resolution that M2 had to skip (the 48px
half-scale class and rarer 42/53/101px classes). After wiring, M2's
explicitly-counted skips must drop to zero. Consumers: detect (M4) uses
every operator here; nothing else in the package does.

## Commit 1 — full oracle dumps

Complete `tools/reference/dump_imageops.py` (M0 shipped the quantization
skeleton). Output to `test/data/imageops/` (float32 LE `.bin` + same-name
`.json` metadata; counts against the 4MB budget — trim cases rather than
precision if exceeded):

| Operator | Inputs | Expected output |
|---|---|---|
| BGR2GRAY | 3 real patches + one 16×16 full-value-range synthetic image | uint8 gray |
| Sobel magnitude | the grays above as float/255 + the V2-96 alpha map | float32 |
| meanStdDev | each image above | (mean, std) doubles |
| TM_CCOEFF_NORMED | 2 real (gray patch, alpha template) pairs + flat search region + constant template + single-pixel perturbation | float32 result matrix |
| resize | V2-96 alpha map → 42 / 48 / 53 (INTER_AREA), 101 (INTER_LINEAR) | float32 |

Generation command and cv2 version go into each `.json`.

## Commit 2 — grayscale + statistics

`src/imageops.ts`:

- `toGrayscale(image: ImageBuffer): Uint8Array` —
  `y = (9798·r + 19235·g + 3735·b + 16384) >> 15` (integer math; RGB
  channel order)
- `meanStdDev(data: Float32Array | Uint8Array): {mean, std}` — OpenCV
  definition (population std, divide by N not N−1; verify against dump)

Tests: grayscale vs dump **byte-exact** (on failure: first check channel
order/formula; only a confirmed platform difference takes the fallback —
|Δ|≤1 with <0.1% deviating pixels, recorded with evidence in
DEVIATIONS.md); meanStdDev with the dual tolerance `1e-6 + 1e-5·|ref|`.

## Commit 3 — Sobel + NCC

- `sobelMagnitude(gray: Float32Array, w, h): Float32Array` — 3×3 Sobel
  (kernels matching OpenCV), BORDER_REFLECT_101 boundaries (index -1→1,
  w→w-2), `sqrt(gx²+gy²)`
- `matchTemplateCcoeffNormed(img, iw, ih, tmpl, tw, th): Float32Array` —
  per-window mean-centered cross-correlation divided by the energy root;
  naive O(n⁴) is fine (tiny windows in this project); calibrate the
  denominator-underflow guard against the dump's flat/constant cases
  (OpenCV's behavior comes from the dump, not from memory)

Tests: Sobel dual tolerance; NCC non-degenerate `absErr ≤ 1e-4`,
degenerate cases match the dump with no NaN/Inf.

## Commit 4 — resize + effectiveAlphaMap wiring

`src/resize.ts`:

- `resizeAreaIntegerFactor(src, sw, sh, factor)`: k×k box mean
- `resizeArea(src, sw, sh, dw, dh)`: general INTER_AREA (pixel-coverage
  weighting: a destination pixel maps back to the source interval
  `[x·sw/dw, (x+1)·sw/dw)` and averages by coverage length; separable in
  2D)
- `resizeBilinear(src, sw, sh, dw, dh)`: half-pixel centers
  `sx = (dx+0.5)·sw/dw − 0.5`, edges clamped

`src/effective-alpha.ts` (corresponds to `effective_alpha_map` +
`create_interpolated_alpha`, watermark_engine.cpp):

```ts
export function effectiveAlphaMap(variant: WatermarkVariant,
  imageWidth: number, imageHeight: number,
  size?: WatermarkSize): {alpha: Float32Array, w: number, h: number}
```
- size defaults from image dimensions; when V2 small and
  `config.logoSize ≠ 36`, scale from that variant's 96px source map
  (<96 INTER_AREA, =48 is the exact integer factor, >96 INTER_LINEAR);
  otherwise return a copy of the source map
- The crop tests explicitly skipped in M2 (48px class) are wired here and
  the skip count drops to zero

Tests: the four resize points (42/48/53/101) vs dump with the dual
tolerance; `effectiveAlphaMap` across the 36/42/48/53/101 image-dimension
classes (construct 1024×572, 1200×700, 1376×768, 3000×1000, …) matches
dump/direct resize.
