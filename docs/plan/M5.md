# M5 — Public API documentation, examples, and package quality

> **Base fact**: this repository is a faithful TypeScript port of
> [GeminiWatermarkTool](https://github.com/allenk/GeminiWatermarkTool) —
> a C++ tool that removes Gemini's visible image watermark via
> deterministic reverse alpha blending. The C++ source (v0.3.2, commit
> `7c6a99f`, checked out at `$GWT_UPSTREAM_DIR`) is the sole behavioral
> authority; we reproduce its behavior, quirks included, never "improve" it.
>
> **Required reading**: no new upstream code — this milestone ports
> nothing. The authoritative inputs are `docs/api-contract.md` (frozen in
> M4) and this repo's own modules/tests. Upstream's README may be
> consulted for user-facing wording, never for behavior claims beyond the
> scope matrix.

Prerequisite: M4 complete (the contract is frozen; this milestone **does
not change the contract**, only finalizes and documents it).

## Context

After M4 the engine is functionally complete but only provably correct to
someone who reads our tests. This milestone makes it usable and
trustworthy for outsiders: an e2e suite that exercises the full public
contract (not just the default path), a real-browser proof that the
zero-dependency claim holds at runtime (the package's core promise is
"runs in browsers" — until Playwright loads the built output in Chromium,
that claim is untested), contributor documentation so external PRs can
follow the equivalence rules, and machine-checked package quality
(publint/attw) so the published artifact resolves correctly in every
consumer setup. No new algorithm work belongs here.

## Commit 1 — e2e contract-matrix tests

`test/e2e.test.ts` (CI patch runs) + `test/golden/e2e-full.test.ts`:

| Case | Assertions |
|---|---|
| Default remove (`default_e2e`) | vs patch-golden-default: inside ±1, outside and A channel byte-exact |
| Skip case | status='skipped' and buffer byte-identical |
| add V1 | vs watermarked ±1 |
| add V2 (extension) | within test:golden via the C++ remove oracle (path built in M2, reused) |
| force | matches golden-force |
| Explicit variant / forced-size | ≥1 each; forced-size uses a **processed** misaligned-output case |
| Invalid ImageBuffer / invalid enum values | error types and messages |

Executed counts close against manifest `eligible_for`.

## Commit 2 — browser smoke + static defenses

- devDep `playwright`; a dedicated CI job:
  `npx playwright install chromium --with-deps` → build → a test page
  doing `import '/dist/index.js'`, running `processImage` on one
  reconstructed case, comparing the result sha256 with the Node-side
  expected value
- The forbidden-import check stays inside `check` (double insurance)

## Commit 3 — docs and examples

- `examples/browser/`: single-page example — `<input type=file>` →
  `createImageBitmap(file, {colorSpaceConversion: 'none',
  imageOrientation: 'from-image'})` → OffscreenCanvas → ImageData →
  `processImage` → PNG download; its own `tsconfig.json`, wired into CI
  typecheck; excluded from the npm package (files whitelist already
  restricts)
- `CONTRIBUTING.md`: dev environment (Node/pip), `npm run check` /
  `test:golden` usage and how to recognize that "skipped golden ≠
  passed", the full kit regeneration flow, a numeric-equivalence rules
  digest (pointing at CLAUDE.md), a PR checklist, the upstream sync policy
  (new upstream version → update kit and manifest first → only then touch
  code)
- Full README: compatibility matrix (mirroring PLAN), install placeholder
  (unpublished), Node + browser usage samples, API reference (excerpted
  from api-contract.md), limitations (SynthID, color management, JPEG
  decoder differences), credits and license

## Commit 4 — package quality gates

- devDeps `publint` + `@arethetypeswrong/cli`; `check` grows to
  `typecheck && test && build && publint && attw --pack`
  (CI runs the full check on one Node version; the rest of the matrix
  runs tests)
