# M2 — Forward/reverse blend (src/blend.ts)

> **Base fact**: this repository is a faithful TypeScript port of
> [GeminiWatermarkTool](https://github.com/allenk/GeminiWatermarkTool) —
> a C++ tool that removes Gemini's visible image watermark via
> deterministic reverse alpha blending. The C++ source (v0.3.2, commit
> `7c6a99f`, checked out at `$GWT_UPSTREAM_DIR`) is the sole behavioral
> authority; we reproduce its behavior, quirks included, never "improve" it.
>
> **Required upstream reading (in full, before writing code)**:
> `src/core/blend_modes.cpp` — the entire file (176 lines); it is the
> line-by-line porting reference for this milestone.

Prerequisite: M1 complete.

## Context

This is the mathematical core the project exists for. Gemini applies its
watermark as `watermarked = α·logo + (1−α)·original` with a white logo
(255); removal solves for `original = (watermarked − α·logo)/(1−α)` —
exact, deterministic reconstruction, no generative inpainting. This
milestone ports those two per-pixel loops: the first code that actually
touches image pixels.

Inputs available at this point: alpha maps (M1), golden blend crops and
the cv2 quantization oracle (M0). Consumers: the `processImage`
orchestration (M4) calls these under detection gating; e2e (M5) verifies
them end to end. The subtle risk here is not the algebra — it is the
quantization law (cvRound half-to-even, see CLAUDE.md rule 5) and the
edge branches (α thresholds, clipping), which is why the test matrix
below is mostly about boundaries, not the happy path.

## Commit 1 — quantization helper + blend implementation

1. `src/quantize.ts`:
   ```ts
   export function roundHalfToEven(v: number): number
   export function quantizeU8(v: number): number  // clamp [0,255] then half-even
   ```
   Semantics are pinned by the cv2 quantization oracle samples committed
   in M0 (under `test/data/imageops/`). Note this is a **different law**
   from `roundHalfAwayFromZero` (position.ts, for integer geometry).
2. `src/blend.ts`:
   ```ts
   export function removeWatermarkRegion(image: ImageBuffer,
     alpha: Float32Array, alphaWidth: number, alphaHeight: number,
     position: Point, logoValue = 255): void
   export function addWatermarkRegion(/* same params */): void
   ```
   Porting points (one-to-one with the C++):
   - Four-edge clipping: `x1=max(0,x) … y2=min(H,y+h)`; return immediately
     on empty intersection
   - Per pixel: skip when α < 0.002; α clamp 0.99 **remove only**;
     remove formula `(w − α·logo)/(1−α)` then `clamp [0,255]`;
     add formula `α·logo + (1−α)·orig` then `clamp [0,255]`
   - Intermediate math in JS doubles (allowed by the equivalence contract,
     CLAUDE.md rule 4); write-back through `quantizeU8`
   - 3 channels processed; with RGBA, skip the A byte (byte-exact
     passthrough)
   - Invalid input (data length ≠ w·h·channels, channels ∉ {3,4}, alpha
     length ≠ alphaWidth·alphaHeight) → `RangeError` with actual vs
     expected in the message
3. Export from `src/index.ts`.

## Commit 2 — unit tests (CI self-contained)

`test/blend.test.ts` branch matrix:

- Quantization: oracle samples point by point (including .5 boundaries and
  saturation; negative halves are outside blend's value domain — test
  them only as `quantizeU8` domain behavior)
- α = 0.0019 / 0.002 / 0.0021 (both sides of the skip threshold)
- α = 0.995 triggers the clamp (remove); contrast case showing add does
  **not** clamp at the same α
- One out-of-bounds clip case per edge + a fully disjoint case
- RGB and RGBA (byte-exact A-channel assertions)
- Three invalid-buffer shapes → RangeError and message
- Roundtrip: the four real source alpha maps × fixed-seed pseudo-random
  content (hand-rolled LCG; Math.random forbidden), add→remove
  max|Δ| ≤ 1

## Commit 3 — golden equivalence tests

1. `test/blend-crops.test.ts` (**CI**): iterate manifest cases whose
   `eligible_for` includes `force_remove`, read
   `test/data/cases/<name>/blend-*`, call `removeWatermarkRegion` in crop
   coordinates (alpha maps: canonical sizes via `getSourceAlphaMap`; the
   48px-class cases are skipped **with an explicit count** until M3 wires
   them, then the count drops to zero) — compare against golden-force:
   inside the watermark region max|Δ| ≤ 1, outside byte-exact.
   **Finally assert executed == eligible − explicitly-skipped.**
2. `test/golden/blend-full.test.ts` (`npm run test:golden`; throws when
   `GWT_REFERENCE_DIR` is missing): the same assertions on full images.
3. add equivalence: `add_v1` cases run add on originals vs watermarked ±1;
   `add_v2_ext` cases write the TS add-V2 outputs into
   `$GWT_REFERENCE_DIR/out-v2add/` and invoke the **C++ binary**
   (`--force --no-legacy`) to remove, comparing against the originals ±1
   (test:golden scope; the test comment states "extension contract:
   oracle is C++ remove, not upstream add equivalence").
