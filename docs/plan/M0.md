## Context — why this milestone exists

This project is a faithful TypeScript port of GeminiWatermarkTool v0.3.2
(C++): a deterministic engine that removes Gemini's visible watermark by
inverting alpha blending. "Faithful" is proven by comparing against
**golden outputs of the reference C++ binary** — not by judgment.

Entering state: the repo has only scaffolding + the position module.
The reference data everything else depends on (fixtures, golden outputs,
detection-score manifest) was produced ad hoc by three Python scripts
that live **only on the maintainer's machine** (`~/gwt-reference/scripts/`)
with hardcoded paths.

This milestone turns that into reproducible, in-repo tooling
(`tools/reference/`) and committed CI test data (`test/data/`). Every
later milestone's equivalence tests consume what M0 produces — without
M0 there is no oracle. It also corrects the README/CLAUDE claims so the
repo never promises more than the plan's scope.

## Commit 2 — manifest schema + regenerated, enriched golden

1. Write `tools/reference/manifest.schema.json`. Required fields per case:

   ```
   name, input: {format: png|jpg, width, height, decoded_pixel_sha256},
   fixture: {variant, margin, logo_size, position{x,y}} | null (negatives),
   eligible_for: [force_remove|add_v1|add_v2_ext|detection|default_e2e|forced_size],
   runs: {
     default: {argv, exit_code, detections: [{variant, spatial, gradient,
       variance, confidence, circuit_breaker, detected, snap_region{x,y,w,h}?,
       removal_position{x,y}?}], output_decoded_sha256?},
     force:   {argv, exit_code, removal_position, output_decoded_sha256},
     forced_size?: same + {flag: force-small|force-large}
   },
   toolchain: {binary_sha256, binary_version, upstream_commit, cv2_version}
   ```

   Notes: scores come from the `-v` log (`Detection: spatial=… grad=…
   var=…` and the circuit-breaker line `Detection: spatial=… < 0.25,
   rejected`), **3 decimal places of precision**; `removal_position` is
   parsed from the debug line `Removing watermark at (x, y)`.
2. `gen_golden.py` gains forced-size runs (`eligible_for: forced_size`):
   - `--force --force-small` on `v2-large-2752x1536`
   - `--force --force-large` on `v2-small-1024x572`
   - `--force --force-large --legacy` on `v1-small-800x600`
   The upstream quirk (position from the dims-based config, template from
   the forced size resolved through effective_alpha_map) is **recorded
   from the actual golden output — never "corrected"**.
3. Full rerun of all three scripts → schema validation → commit
   `test/data/manifest.json`.

Verification:
`python3 tools/reference/validate_manifest.py test/data/manifest.json`
(the validator ships in the same commit as the schema).

## Commit 3 — patch data generation and commit

New script `tools/reference/make_patches.py`:

1. **Detection-level patches** (for detection / default_e2e / forced_size /
   negatives). Bbox computation per case:
   ```
   rects = []
   for variant in [V2, V1]:                # order the default run tries
       config = get_watermark_config(W, H, variant)
       pos = bottom-right position formula; pad = 3 if (variant==V2 and small) else 0
       roi = clamp(pos ± pad + logo)       # mirrors detect_one_variant
       ref_h = min(roi.y1, config.logo_size)   # variance reference region
       rects += [roi, (roi.x1, roi.y1-ref_h, roi.width, ref_h)]
   forced_size cases additionally append the roi/reference rects of their
   forced combination
   bbox = union(rects) expanded by 8px, clamped to the image
   ```
2. **Blend crops** (for force_remove / add): watermark region ±8px.
3. Output `test/data/cases/<name>/`:
   `meta.json` (original_size, patch bbox, blend bbox, eligible_for copy) +
   `patch-watermarked.png`, `patch-original.png`, `patch-golden-force.png`,
   `patch-golden-default.png` (when processed), the three `blend-*.png`;
   the q90 case's input patch is cropped from **decode-normalized pixels**
   (the TS side never decodes JPEG).
4. Self-check (enforced at generation time): every patch bbox covers all
   of its rects, otherwise the script fails; `du -sk test/data` < 4096.

Same commit ships the TS-side rebuild helper `test/helpers/reconstruct.ts`:
zero-fill a buffer of `original_size`, place the patch, return an
`ImageBuffer`.
